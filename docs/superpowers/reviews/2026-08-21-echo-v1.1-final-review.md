## Strengths

**The refactor kept its contract.** The 32 original tools were mechanically diffed old-vs-new: every name, zod schema, `.optional()`, description string, and group membership survives the split of `src/mcp/register-tools.ts` into `src/mcp/tools/*.ts`. The only client-visible deltas are additive — `tabs_new` gains optional `incognito`, `tabs_list` gains `incognito` and maps `favicon` to a boolean, and `recording_play`'s message became a range form. Thirty of thirty-two handler bodies are byte-identical after whitespace normalization. That is a rare outcome for a 429-line file exploded into ten.

**The tests are real, not theatre.** The prebuilt suite runs clean: 57 pass, 0 fail, and 57 is the honest count.

- `test/unit/pdf-text.test.ts:150` is an actual 70 MB zip bomb that asserts refusal *and* that the sibling stream still parses.
- `test/unit/visual.test.ts:45` ships an independent CRC32 so fixtures don't lean on the code under test.
- `test/unit/scheduler.test.ts` holds a run open mid-replay to prove `tick()` never overlaps.
- `scripts/test-tools.mjs:230` asserts `listTools()` returns exactly 69 over the wire, and `:541` asserts the called-set covers everything but the one declared skip (`search_web`, live Google) — so the harness cannot silently rot as tools are added.
- The `/health` readiness poll the ledger asked for landed at `scripts/test-tools.mjs:204`.

**Anti-drift guards.** `test/unit/tool-registration.test.ts` calls the real `registerTools` against a stub server and asserts every registered description equals its manifest entry; `test/unit/skill-tree-doc.test.ts` asserts the shipped markdown quotes each description verbatim. Docs rot is now a test failure. The manifest matches registrations exactly: 69 entries, 69 registrations, zero mismatches, and the 40/68/69 arithmetic checks out against counted data rather than comments.

**The renderer rewrite is clean.** Zero `innerHTML` / `insertAdjacentHTML` / `outerHTML` / `eval` anywhere in `src/renderer/` — everything goes through `h()` in `src/renderer/ui/dom.ts:31`, which uses `textContent` and `createTextNode`. The CSP at `src/renderer/index.html:7` matches the plan's required policy character for character. All 65 element IDs from the old `index.html` survive (24 new ones added); all 11 old `data-transfer` keys plus the 4 new ones are wired to `window.lb.setTransfer` at `src/renderer/ui/settings.ts:129-135`; every one of the 70 interactive elements in the new HTML has a handler. 30 of 31 old behaviours are preserved. `styles.css` has zero `url()`, `@import`, `@font-face`, or remote hosts; all icons are inline SVG built with `createElementNS` (`src/renderer/ui/dom.ts:266-333`) explicitly to avoid a webfont.

**The favicon/CSP problem was solved the right way.** The Task 3 ledger note warned that remote favicon URLs would be blocked by `img-src 'self' data:`. Icons are now fetched in main, decoded and re-encoded through `nativeImage`, and cached with an LRU (`src/main/browser.ts:1736`). Tab thumbnails likewise (`browser.ts:620-630`). `src/renderer/ui/tabs.ts:159-161` installs an `error` handler that degrades to the globe glyph.

**No JS injection sinks.** Every client-supplied value reaching `executeJavaScript` is `JSON.stringify`'d first — refs, selector arrays, storage keys and values, key chords. `cssEscape` (`src/main/browser.ts:2211`) correctly escapes `\` and `"` for the locator attribute. The only raw-source path is `evaluate`, which is by design and gated behind both `toolsInteract` and an explicit user switch.

**`src/main/scheduler.ts`** is the best-written new module: clamped inputs, `busy` re-entrancy guard, cancellation-during-tick handled, validated on load, `unref`'d timer, injected clock.

**Two behavioural changes in the renderer are improvements, not regressions:** `renderSettings` early-returns while the settings page is hidden (`src/renderer/ui/settings.ts:196`, covered on the way in by `openSettingsSection`), and `#reload` now calls `lb.stop()` while loading (`src/renderer/main.ts:253-256`) instead of reloading behind a stop icon.

## Issues

### Critical (Must Fix)

#### C1. `normalizeUrl` passes every URL scheme through, so the default-on tool set reads any file on disk

**Where:** `src/main/browser.ts:2118-2128`

```ts
if (/^[a-z]+:/i.test(trimmed)) return trimmed;
```

**What:** `navigate("file:///C:/Users/<u>/.ssh/id_rsa")` loads the file, and `html` / `get_text` / `pdf_text` return the contents as clean text. `toolsBrowse` and `toolsRead` are both **on by default**, so a fresh install hands any connected assistant arbitrary local file read with no toggle flipped. The same passthrough is reachable from a hostile *page* via `setWindowOpenHandler` (`src/main/browser.ts:1763`), which calls `createTab(url)` from the main process and therefore bypasses Chromium's normal web→file navigation block.

**Why:** This scheme passthrough predates the branch, but v1.1 is what turns it into a clean text-extraction primitive available by default. A consumer browser that ships an assistant channel must not make "read any file on this machine" the zero-configuration state.

**How:** Allowlist schemes (`http`, `https`, `about`, `data`) on the MCP-driven navigation path and on `setWindowOpenHandler`. Keep `file:` for the renderer omnibox if desired, or confine it to `downloadsDir()`. `pdfText`'s deliberate `file:` support (`src/main/browser.ts:1533`) can keep an explicit exception.

#### C2. Pause and the tool-group switches are not enforcement points

**Where:** `src/main/index.ts:673-683` and `src/mcp/tools/_helpers.ts:32`

**What:**

1. The `Scheduler` run callback checks `recorder.isRecording()` and `recorder.isPlaying()` but **not `activity.isPaused()`**. The user presses Pause, sees "Assistant paused" in the pill (`src/renderer/ui/assistant.ts:135`), and a scheduled recording keeps driving the browser every N minutes.
2. `ToolDeps.prefs` is a snapshot taken when a session registers its tools. Turning **off** `toolsState` or `evaluate` in Settings does not revoke it from an already-connected assistant. The UI only says "Reconnect after changing this" (`src/renderer/index.html:208`, `:224`), which reads as "new tools won't appear," not "turning off doesn't revoke."

**Why:** Pause is this release's headline user-safety control. A bypass is a correctness bug in the promise it makes, and a toggle that cannot revoke is not a security control.

**How:** Add `if (activity.isPaused()) return { ok: false, message: "Skipped: the assistant is paused." };` to the scheduler callback. Re-check the live pref for the tool's group inside `define`'s wrapper in `src/mcp/tools/_helpers.ts:58` so the toggle becomes a real kill switch.

### Important (Should Fix)

#### I1. One `Session` and six listeners stranded per incognito tab

`src/main/browser.ts:466` gives every incognito tab a unique `incognito-${id}` partition; `closeTab` (`:537`) never releases it, and Electron 36 has no public `Session.destroy()`. Each closed incognito tab permanently leaks an in-memory cookie jar, cache, and the `onBeforeSendHeaders` / `onHeadersReceived` / `onBeforeRequest` / `onCompleted` / `onErrorOccurred` / `will-download` handlers, all closing over `this`. Fifty open-and-close cycles leaves fifty live sessions.

**Fix (matches Chrome's model):** use one shared `incognito` partition and call `clearStorageData()` + `clearCache()` when the last incognito tab closes. `Tab.partition` is already stored and currently unused — this is what it is for.

#### I2. Closing the last tab preserves incognito and per-tab state

`src/main/browser.ts:538-541` — when `tabs.size <= 1`, `closeTab` navigates home and returns without resetting `tab.incognito`, `tab.partition`, `tab.console`, `tab.network`, or `tab.contentType`. Close your only incognito tab and you are still in the incognito partition, still flagged incognito, still not recording history, with the previous site's console log attached. New behaviour in this branch.

#### I3. Playwright attachment has no failure or disconnect handling

`src/main/browser.ts:446-458` and `:1828`.

- `this.pw` is set once and never cleared; there is no `browser.on("disconnected")`. `playwrightPage()` does `this.pw.contexts().flatMap(...)` outside any try/catch, so one dropped CDP socket throws past the Electron fallbacks and permanently breaks `click`, `type`, `select`, `hover`, `double_click`, `right_click`, `press`, `shortcut`, `screenshot`, and `watch` until Echo restarts.
- No in-flight dedupe, so concurrent tool calls open and leak duplicate CDP connections. `favicon()` at `:1736` already models the correct pattern.
- Failure is not cached, so with CDP unavailable *every* `click` pays the full 20 × 250 ms retry loop before falling back.

#### I4. Unfiltered blocking `onBeforeRequest` on every subresource

`src/main/browser.ts:367` registers with no filter, while its sibling `trackContentType` (`:312`) is correctly filtered to `mainFrame`. Every image, font, script, and XHR on every tab makes a blocking round-trip into the main process — the same thread as the UI and the MCP server — and each one runs a linear scan over all tabs.

**Fix:** filter to the resource types actually logged.

#### I5. `History.save()` writes the whole file synchronously on every navigation and title update

`src/main/history.ts:72-79`, called from `add` and `updateTitle`, which fire from `page-title-updated` (`src/main/browser.ts:1771`). SPA sites update their title on every route change; at the 5,000-entry cap that is a ~750 KB synchronous write per event on the main thread. Debounce it.

#### I6. Persisted schedules have no user-facing surface and outlive their tool group

`schedules.json` survives restart and `scheduler.start()` runs unconditionally (`src/main/index.ts:684`), but nothing in `src/renderer/` mentions schedules — the user cannot see or cancel one. An assistant can plant a recurring browser-driving job, the user turns `toolsQa` off, and it keeps firing forever with no way to stop it short of deleting the file.

**Fix:** add a Schedules list to the Recordings settings page. This also subsumes the ledger's "schedule for a deleted recording keeps retrying."

#### I7. `upload_file` is an unrestricted local-file read, and the UI copy does not say so

`src/main/browser.ts:1152` + `src/mcp/tools/interact.ts:147` — arbitrary absolute paths from the MCP client, validated only with `fs.existsSync`, handed to `setInputFiles`. Navigate to an attacker page with a file input, upload `id_rsa` or `mcp-token.txt`, done.

It is correctly gated behind `toolsInteract` (default off), but `src/renderer/index.html:285` describes the group as "hover, drag, right-click, dialogs, frames, zoom, upload" — nothing tells the user that switch grants read access to their entire disk. Either confine paths to `downloadsDir()` / a user-picked allowlist, or say it plainly in the toggle copy.

The same applies to `cookies_get` under "Sessions and state" (`src/renderer/index.html:295`): "This reaches your signed-in sessions" understates a full session-token dump, since `src/mcp/tools/state.ts:28-36` returns raw cookie values including `httpOnly` ones for every domain in the profile.

#### I8. Consent and legal copy were not updated for the 1.1 capability set

`legal/` has an empty diff in this branch, and `src/renderer/index.html:535` still says a connected assistant may "navigate, click, type, capture screenshots, read pages, and start or play recordings." It does not mention reading and writing cookies, local and session storage, clearing site data, uploading local files, running arbitrary JavaScript, or scheduling unattended replays. For a product whose entire risk story is what the assistant can do, this is the document that has to be right.

#### I9. Test-mode guard fails open

`src/main/index.ts:49-53` — when `ECHO_TEST=1` is set without `ECHO_TEST_USERDATA`, it logs and calls `app.exit(3)`, then module evaluation continues. `app.exit()` should terminate, but if it ever does not, `whenReady` runs `prepareTestProfile()` (`:587`) against the **real** profile, silently switching on all 69 tools and `evaluate`.

**Fix:** set a `refused` flag and bail in `whenReady` too. Separately, `ECHO_TEST` survives into the shipped `out/main/index.js`, so a debug path that force-enables `evaluate` ships to users; compiling it out under `--prod` is cheap insurance.

The mandatory throwaway-profile design itself is good — this is defense in depth.

#### I10. `snapshotByRef` is hub-global, so refs bleed across tabs

`src/main/browser.ts:168`, cleared in `did-navigate` only when the navigating tab is active (`:1776`), never in `selectTab` or `closeTab`. Snapshot tab A, switch to tab B, `click("e5")` → the click resolves in B while the *recorded* selectors come from A. Concurrent `snapshot()` calls from two MCP clients renumber each other's refs (`:897`). Both fail silently on the wrong element.

Pre-existing, but `frame_select` and the multi-client story amplify it. Moving the map onto `Tab` is a five-line change — and it is exactly the per-tab discipline the `frameIndex` comment at `:118` was careful about.

#### I11. Testing gaps that matter

- `.github/workflows/release.yml` runs only on `workflow_dispatch` and `v*` tags. **There is no CI on push or pull request** — 57 good tests gate nothing during development.
- `test/unit/tool-registration.test.ts` turns all prefs on, so it never checks that a tool's *registered group* matches its manifest group, and `_schema` is discarded (`:32`) so schema drift is invisible. A per-group run (one group on, assert the exact set) would close both.
- `src/main/browser.ts` at 2,229 lines has zero unit coverage, and its two most testable pure functions — `normalizeUrl` and the download-path join — are both where real bugs live.
- `scripts/check-packaging.js` requires three *test* files that never ship (`:16-17`), validates `build.mac` only while Windows is the shipping target, and silently no-ops its build-output checks on a clean tree (`:60-68`) — it exits 0 having verified nothing.

### Minor (Nice to Have)

- `src/main/browser.ts:1560` — `searchWeb` creates a tab per call and never closes it; twenty searches, twenty Google tabs. Pre-existing, one-line fix.
- `src/main/browser.ts:2105` — favicon size cap is checked against declared `content-length`, then `await response.arrayBuffer()` buffers the whole body before the real check. A server that omits or lies about the header streams unbounded bytes into main. The icon URL is also fully page-controlled with no same-origin check, giving a page a blind SSRF from the main process using the tab's cookie jar.
- `src/main/browser.ts:1719-1721` — a page-supplied `data:` favicon is passed to the renderer's `<img src>` verbatim (length-checked only, MIME unvalidated), unlike the http(s) path which is re-encoded through `nativeImage`. Not exploitable — `<img>` does not execute script for `data:image/svg+xml`, and non-image data URLs hit the error handler — but it is the one unvalidated page-controlled string reaching an `src`.
- `src/main/mcp-http.ts:103` — `/health` answers **before** the auth check at `:130`, disclosing version, live client count and every LAN IPv4 unauthenticated, on a `0.0.0.0` bind (`src/main/paths.ts:6`). `:131` is also a non-constant-time token compare. All pre-existing.
- `src/main/index.ts` — `app.on("web-contents-created")` (`:747`) is registered *after* `createWindow()` (`:731`), which creates the first tab, so the first tab's webContents never gets `before-input-event`. Ctrl+T/L/K/D and Ctrl+1-9 are dead while focus is in tab one. Pre-existing ordering, but v1.1 adds five new shortcuts that inherit it. Move the registration above `createWindow()`.
- `src/renderer/index.html:59-60` — **`#led` satisfies the plan's ID constraint by letter, not function.** The element is kept but `hidden`, and no renderer TS references it; the old renderer bound it four ways including `led.addEventListener("click", … openSettings("connections"))`. Net effect: there is no longer a one-click toolbar path to Settings → Connections — the assistant pill's popover only offers "Open Activity" (`src/renderer/ui/assistant.ts:391-395`), so Connections is reachable only via `#menu` → Settings or Ctrl+`,`. Any CSS or screenshot check keyed on `#led.on` is also now permanently unmatched. Add a Connections button to the pill popover.
- `src/main/index.ts:172-177` — **Escape does not close the command palette while Settings is open.** `handleShortcut` swallows Escape whenever `hub.isSettingsOpen()`, sends `close-settings`, and calls `preventDefault()`, which suppresses dispatch to the chrome document. `hideSettings()` (`src/renderer/ui/settings.ts:649-653`) does `releaseAll` + `remeasureToasts` but never `closePalette()`, and neither the palette's own Escape handler (`src/renderer/ui/palette.ts:123-126`) nor the window-level `closeOverlays` (`src/renderer/main.ts:280`) gets to run. Reachable: open Settings → Ctrl+K → Escape → settings closes, palette stays. A second Escape then works, and the backdrop click is a fallback, so it is recoverable. One-line fix: have `hideSettings()` call the shared `closeOverlays()`.
- `src/renderer/main.ts:270-279` — the renderer's own Ctrl+K / Ctrl+Shift+P binding is dead code: `handleShortcut` returns true for those keys and `src/main/index.ts:227` calls `preventDefault()`, suppressing dispatch to the chrome document. Harmless (`openPalette` is idempotent), but the justifying comment at `:273-274` is factually wrong about which handler covers the chrome.
- `src/main/browser.ts:1775` — `did-navigate` clears `frameIndex`, `favicon`, and the thumbnail but not `tab.console`, so `console_errors` reports the previous site's errors as this site's. Pre-existing.
- `src/main/browser.ts:294` — `setSavePath(path.join(downloadsDir(), item.getFilename()))` bypasses Chromium's uniquifier, so two `report.pdf` downloads silently clobber each other. Traversal is not currently reachable (Chromium sanitizes the name) but nothing here enforces that; use `path.basename()` + uniquify.
- `src/mcp/tools/qa.ts:91-96` — `let ok = url.includes(pattern)` is dead, immediately overwritten. Also `new RegExp(pattern)` on an unvalidated client string compiles in the main process; a catastrophic-backtracking pattern freezes UI, IPC and MCP together. Cap the pattern length.
- `test/unit/skill-tree-doc.test.ts:56` — `entry.description.replace(/\|/g, "\|")` is a no-op; `"\|"` is just `"|"` in TS. Dormant (no description contains a pipe), but the escape it claims to make does not happen.
- `src/preload/index.ts:43` — `setSettings(open: boolean)` toggles the settings *panel* while `updateSettings` writes app settings. Rename to `setSettingsOpen`.
- `src/main/activity.ts:16` — `clear()` does not reset `seq`, so the count shown after "Clear" is unchanged. Probably intended; surprising in the UI.
- `src/preload/page.ts:188` — `ipcRenderer.sendSync("echo:dialog")` gives a page a synchronous main-process block per `confirm()` call. A `for(;;) confirm('')` loop hard-locks the whole app including other tabs and the MCP server. Consider a per-tab rate limit or a "suppress further dialogs" latch.
- `package.json` has no `publish` or `repository`, yet electron-builder still emits `latest.yml` / `app-update.yml` inferring a GitHub feed the release workflow never uploads. Harmless now, confusing later.
- CI pins `node-version: 20`. `zlib.crc32` (used at `test/unit/visual.test.ts:167`) was backported to 20.15.0, so this is **not** currently biting — but any pin to an exact 20.0–20.14 fails. Bump CI to 22 and the footgun is gone. Production `visual.ts` implements its own CRC32 and has no such dependency, which was the right call.
- Migration nuance: `toolsRead` defaults to `true` for upgrading users too, so an existing user silently goes from 32 to exactly 40 tools — precisely the Cursor cap the README warns about at `:222`. Consider defaulting it off for profiles that already have a `transfer-prefs.json`.

## Recommendations

1. **Fix the five must-fixes, then merge.** Four are under ten lines each; only the incognito session change needs real thought.
2. **Add CI on push and pull request.** The suite is genuinely good and currently gates nothing. Run `test:unit` + `tsc --noEmit` + `packaging:check` on every PR, on Node 22.
3. **Extract `PwAttachment` from `browser.ts` first** — `connectPlaywright`, `playwrightPage`, `requirePlaywrightPage`, `pwTarget`, `withPage`, `hookDialogs` (`:446-458`, `:1820-1935`). It is the cleanest seam and all three I3 defects live inside it. Then `SessionInstrumentation` (`:284-444`) and `Capture` (`:700-846`). Move `snapshotByRef` onto `Tab` while in there.
