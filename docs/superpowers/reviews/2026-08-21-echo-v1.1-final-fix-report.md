## 1. URL scheme allowlist on assistant-driven navigation (C1)

**New file `src/shared/url-policy.ts`** — a pure module (no `electron` import, so it unit
tests) exporting:

- `isAssistantNavigable(input: string): boolean`
- `ASSISTANT_NAV_REFUSAL` — `"Echo only opens http(s) pages from an assistant. Open local files yourself in the address bar."`

Policy: `http:` / `https:` / `data:` pass; `about:` passes only as `about:blank` (with an
optional `?`/`#` tail); every other scheme is refused. Input with **no** scheme passes,
because `normalizeUrl` turns it into `https://…` or a Google search and can never reach
another scheme — so checking the raw input is equivalent to checking the normalized URL
without having to move `normalizeUrl` (and its `HOME_URL` dependency) out of `browser.ts`.

**Enforcement points** — two new hub methods in `src/main/browser.ts`, so there is exactly one
door rather than a check per call site:

- `assistantCreateTab(url?, opts?)` (before `selectTab`) — throws `ASSISTANT_NAV_REFUSAL`, else delegates to `createTab`.
- `assistantNavigate(url, tabId?)` (after `navigate`) — same shape.

Callers switched to them:

| Path | File |
| --- | --- |
| MCP `navigate` | `src/mcp/tools/browse.ts:60` |
| MCP `tabs_new {url}` | `src/mcp/tools/browse.ts:26` |
| MCP `search_web` | `src/main/browser.ts` `searchWeb` (`assistantCreateTab`) |
| Recording replay `navigate` | `src/main/recordings.ts:219` |
| Recording replay `newTab` | `src/main/recordings.ts:224` |
| Page `window.open` | `src/main/browser.ts` `attachListeners` — `if (isAssistantNavigable(url)) this.createTab(...)`, still `{ action: "deny" }` either way |

Tools already wrap their bodies in `try/catch → err(e)`, so the throw surfaces as
`isError: true` with the refusal text — no new error plumbing.

**Unchanged on purpose:** the omnibox `navigate` IPC (`src/main/index.ts:316`), the menu/
shortcut `createTab` calls, and `pdfText`'s deliberate `file:` support. The user typing
`file:///…` still works.

`search_web` builds its own fixed `https://www.google.com/search?…` URL from an encoded
query, so it had no scheme exposure to begin with; routing it through the guard is belt and
braces and is commented as such.

**Tests:** `test/unit/url-policy.test.ts` — 5 tests covering web URLs (including a `file:` URL
smuggled in a query string, which stays allowed because it is not the navigation target), bare
words/hosts/empty, `about:blank` vs `about:config` vs `about:blankextra`, and a refusal list
(`file:`, `FILE:` with surrounding whitespace, `javascript:`, `chrome:`, `devtools:`,
`view-source:`, `blob:`, `ftp:`, `ws:`, `filesystem:`, and a bare Windows path `c:\…`).

## 5. Blocking `onBeforeRequest` is filtered (I4)

`src/main/browser.ts` — one `NETWORK_FILTER` shared by `onBeforeRequest`, `onCompleted`, and
`onErrorOccurred` so entries can never arrive half-logged:

```ts
const NETWORK_FILTER: Electron.WebRequestFilter = {
  urls: ["*://*/*"],
  types: ["mainFrame", "subFrame", "xhr", "webSocket"],
};
```

Images, scripts, stylesheets, fonts, and media no longer make a blocking round-trip into the
main process (which is the UI thread *and* the MCP server thread) and no longer run the linear
scan over all tabs.

Two corrections against the brief, both forced by Electron:

- **`fetch` is not a resource type.** Chromium reports `fetch()` as `xhr`; there is no `fetch` value.
- **`other` is not filterable.** Passing it makes Electron throw `TypeError: Invalid type other` out of `webRequest.onBeforeRequest` — which the first `test:tools` run caught as an unhandled rejection in `prepareSession` that left the app with no active tab. Dropped. The consequence: the few requests Chromium classifies as `other` (beacons, some worker traffic) are no longer in `network_log`. Documented in the constant's comment.

`network_log` description updated, byte-identical in `src/shared/tool-manifest.ts`,
`src/mcp/tools/qa.ts`, and `skills/ECHO-SKILL-TREE.md:473`:

> Recent document and API requests on this tab (method, url, status, type, ms, bytes), newest first. Images, scripts, styles and fonts are not logged.

The prose line at `skills/ECHO-SKILL-TREE.md:260` was updated to match.

## Concerns

1. **`localhost:3000` is now refused from an assistant.** `normalizeUrl`'s scheme test (`/^[a-z]+:/`) treats `localhost:` as a scheme, so `isAssistantNavigable` sees an unknown scheme and refuses. This is not a regression in reachability — `normalizeUrl` already returned `"localhost:3000"` verbatim, which `loadURL` cannot load — but the failure message changed from a load error to the refusal text. `http://localhost:3000` works. Worth fixing in `normalizeUrl` itself (treat `host:port` as a bare host) rather than in the policy.
2. **`other`-typed requests dropped out of `network_log`.** Forced by Electron's filter (see item 5). Beacons, `sendBeacon`, and some worker traffic are no longer visible. If that matters, the alternative is an unfiltered non-blocking `onCompleted`/`onErrorOccurred` pair with only `onBeforeRequest` filtered — at the cost of `pendingRequests` misses for those types.
3. **The scheduler pause check is not unit-covered** (see item 2). It is an inline closure in `index.ts`; extracting it into its own module would make it testable and is the obvious follow-up.
4. **The revoke guard adds a `getTransferPrefs()` file read per tool call.** It is a small synchronous `readFileSync` + `JSON.parse` on the main thread on every MCP call. Correct and cheap at human tool-call rates, but it is a new per-call disk touch; an mtime-cached read would remove it if it ever shows up.
5. **I2 is still open and now interacts with the incognito change** — closing your only tab (`tabs.size <= 1`) navigates home without clearing `tab.incognito`, so the shared incognito session is never released in that path and the tab stays flagged incognito.

## I2. Closing the last tab now closes it

`src/main/browser.ts` `closeTab`. The old `if (this.tabs.size <= 1) { void this.navigate(this.homeUrl); return; }`
kept the tab and everything on it. Now `requireTab(id)` runs first, and when it is the only tab
a fresh normal tab is created (`createTab(this.homeUrl, { record: false })`) before the close
falls through to the ordinary path. The closing tab therefore takes its `incognito` flag,
partition, console buffer, network ring, `contentType`, frame selection (`frameIndex` /
`frameUrl`), per-tab snapshot map, thumbnail and dialog state with it, and
`releaseIncognitoIfLast()` runs, so closing your only incognito tab clears the shared
incognito session.

`createTab` calls `selectTab`, which detaches the old view, attaches the new one and calls
`layout()`, so `activeId` is already the new tab when the close runs: the `this.activeId === id`
branch is skipped and the close ends in a single `onChange()`. The renderer sees one tab
(`order` is `[newId]`), never zero. Recording is not polluted — the replacement tab is created
with `record: false`.

## I10. `snapshotByRef` moved onto `Tab`

`src/main/browser.ts`. The hub field is gone; `Tab` gains `snapshotByRef: Map<string, SnapshotItem>`,
initialised in `createTab`.

- `snapshot()` takes `requireActive()` up front and fills that tab's map (clear + set, so the
  map identity stays with the tab).
- `resolveSelectors()` reads `this.active()?.snapshotByRef.get(ref)`.
- `selectFrame()` clears `tab.snapshotByRef` on both paths (main frame and a chosen frame).
- `did-navigate` clears `tab.snapshotByRef` unconditionally instead of only when the
  navigating tab happens to be active.

A ref from tab A used on tab B now finds no cached entry, and `data-lb-ref="e5"` was only ever
written into A's document, so the existing DOM lookup fails and the tool returns the unchanged
`No element with ref e5. Call snapshot first.`

## I5. `History.save()` debounced, flushed on quit

`src/main/history.ts`: `save()` is now a 500 ms trailing timer (`SAVE_DEBOUNCE_MS`) that sets a
`pending` flag; the timer is `unref()`d (via a `{ unref?: () => void }` cast, so it type-checks
regardless of the `setTimeout` return type) so a queued write never holds the process open. The
actual `mkdirSync` + `writeFileSync` moved into a new public `flush()`, which clears the timer
and returns immediately when nothing is queued. `clear()` calls `save()` then `flush()`:
erasing history is a privacy action and is written through.

`src/main/index.ts` `app.on("before-quit")` now calls `history?.flush()` next to
`scheduler?.stop()`.

`test/unit/history.test.ts`: the existing test gained `h.flush()` before it reloads from disk
(semantics unchanged, test adjusted). New test "history writes are debounced: a burst of adds
is one write, flush persists it" — two adds leave `history.json` absent, one `flush()` writes
both entries, deleting the file and flushing again produces nothing (proving the burst cost
exactly one write), and a further add + flush persists three entries. No `fs` spy: the unit
tests are esbuild CJS bundles, where each module gets its own `__toESM` view of `node:fs`, so a
patched `writeFileSync` would not be observed by `history.ts`. File presence is the reliable
counter here.

# Pass 3 — scoped re-review follow-ups

**Base:** `8c7ed36` · **Date:** 2026-08-21 · One commit, no push, no tag, no install.

## 1. (Important) `prepareSession` registered a `will-download` listener per incognito tab

`src/main/browser.ts`. Pass 1 moved every incognito tab onto one shared `incognito` session,
but `prepareSession` still ran in full for each new private tab. `trackContentType` and
`trackNetwork` already had their own WeakSet guards; `applyChromeSession` and the
`ses.on("will-download", ...)` registration did not, so the shared session accumulated one
download listener per incognito tab ever opened — duplicate `Downloads.track` rows for a single
download, and a `MaxListenersExceededWarning` at the tenth tab.

Added `private preparedSessions = new WeakSet<Session>()` and an early return at the top of
`prepareSession`, which now covers `applyChromeSession` and the download listener as well. The
inner WeakSets stay: they still guard the persistent session's own single-listener contract and
cost nothing.

## 2. Skill tree prose said an incognito tab has its own cookie jar

`skills/ECHO-SKILL-TREE.md:250` now reads: "incognito tabs share one memory-only cookie jar that
is cleared when the last of them closes, keep nothing on disk, and write no history." Prose only
— every table row is byte-identical, so the drift guard in `check-packaging.js` is unaffected.

## 3. `closeTab` while Settings is open could strand `activeId`

`selectTab` early-returns when `settingsOpen`, so closing the active tab from the Settings page
left `activeId` naming a deleted tab. The pass-2 last-tab path made that reachable one more way.
Two minimal changes:

- `closeTab`: when `settingsOpen`, set `this.activeId = next ?? null` directly and `onChange()`,
  instead of calling `selectTab` (all views are detached under Settings, so nothing needs
  attaching yet).
- `setSettingsOpen(false)`: no longer trusts `this.activeId`. It selects `activeId` only if
  `this.tabs.has(it)`, otherwise the last id in `this.order`, and creates a tab when the strip is
  empty.
