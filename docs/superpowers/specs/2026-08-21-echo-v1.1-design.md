# Echo v1.1 — expanded MCP tool set and UI redesign

Date: 2026-08-21. Status: approved.

## Goal

Ship Echo 1.1.0: add 36 MCP tools across four new, individually toggleable groups, rebuild the renderer with a modern visual identity (light/dark, command palette, tab previews, lightweight assistant activity), and keep every existing tool, IPC channel, setting, and connect flow working unchanged. Produce the Windows installer; do not push.

## Non-goals

- No framework port (renderer stays vanilla TS + esbuild).
- No cloud features, accounts, or telemetry.
- No changes to the MCP transport, bridge, auth token, or connect-client writers beyond what new state requires.

## Architecture

Layered extension of the current structure:

```
src/main/          Electron main (BrowserHub, MCP HTTP, connect clients, prefs)
src/mcp/           registerTools(server, deps)  ->  split into src/mcp/tools/<group>.ts
src/renderer/      index.html + styles.css + main.ts  (rewritten, same IPC contract + additions)
src/preload/       contextBridge API (extended with new channels)
src/shared/        types shared by main/preload/renderer
scripts/           build, packaging, tests
```

### New main-process modules

| Module | Purpose | Persistence |
| --- | --- | --- |
| `activity.ts` | Ring buffer (200) of tool calls `{id, tool, startedAt, ms, ok, client, summary}`, `paused` flag, emits state to renderer. Wraps every tool handler. | memory only |
| `settings.ts` | App settings `{theme: system/light/dark, compactChrome, homeUrl, evaluateEnabled}` | `userData/settings.json` |
| `history.ts` | Visit log `{url, title, visitedAt}` (cap 5000), substring search, fed from `did-navigate` and `page-title-updated`. Incognito tabs do not write. | `userData/history.json` |
| `bookmarks.ts` | `{id, url, title, createdAt}` list/add/remove | `userData/bookmarks.json` |
| `downloads.ts` | Tracks `will-download` items `{id, filename, path, bytes, state, startedAt}` | memory + files already on disk |
| `scheduler.ts` | Interval jobs that replay a recording `{id, recordingId, everyMs, nextRunAt, lastResult}`; runs only while Echo is open | `userData/schedules.json` |
| `visual.ts` | PNG decode (zlib inflate, filters 0-4, 8-bit RGB/RGBA only) + pixel compare -> `{changedPct, width, height, diffPng}`; baselines in `userData/baselines/<name>.png` | files |
| `dialogs.ts` | Per-tab dialog policy `{action: accept/dismiss, promptText}` applied via Playwright `page.on("dialog")` when available; without Playwright the tool reports "policy set; applies when Playwright attached". Records last dialog `{type, message, handledAs}` | memory |
| incognito (inside browser.ts) | `createTab(url, {incognito})` uses `session.fromPartition("incognito-<id>")` (no `persist:` prefix) | none |

### BrowserHub additions

`hover(ref)`, `doubleClick(ref)`, `rightClick(ref)`, `drag(fromRef, toRef | {dx,dy})`, `shortcut(chord)`, `uploadFile(ref, paths[])`, `listFrames()`, `selectFrame(index|null)` (snapshot/click scope), `zoom(factor|reset)`, `evaluate(js)`, `getText(ref?)`, `find({text?, role?, label?})`, `links(filter?)`, `tables()`, `forms()`, `pageInfo()`, `html(ref?, maxChars)`, `pdfText()`, `cookies*`, `storage*`, `clearSiteData(origin?)`, `perfTiming()`, `networkLog()` (ring 200 of all requests per tab: method, url, status, type, ms, bytes), `favicon` on `TabInfo`, `reorderTab(id, index)`, `tabThumbnail(id)`.

Each new method uses `withPage(pw, fallback)` like the existing ones. Where no `executeJavaScript` fallback is possible (drag, upload, dialogs) the tool returns an `isError` message naming the limitation.

### Tool contracts (summary)

All tools return text (JSON where structured) or `isError` text. Caps: `html` 50 KB, `get_text` 40 KB, `evaluate` result 20 KB, `tables` 30 rows per table by default (`maxRows` param), `links` 300, `network_log` 200.

- `find {text?, role?, label?, limit=20}` -> refs from a fresh snapshot whose accessible name/role match (case-insensitive substring); refs are valid for click/type.
- `assert_*` -> `PASS ...` / `FAIL ...` text and, if a test run is active, increments `assertions`/`failures` like `test_assert_text`.
- `visual_baseline {name}` saves current viewport PNG; `visual_diff {name, threshold=0.5}` -> `{changedPct, pass, diffPath}`. Size mismatch -> FAIL with both sizes.
- `schedule_recording {recordingId, everyMinutes, action?: add/list/cancel, id?}`.
- `run_recording_steps {id, from=0, to?}` plays a slice through the existing Recorder.
- `dialog {action: accept/dismiss, promptText?}` sets policy; returns last dialog seen.
- `cookies_set {name, value, url, expiresDays?, httpOnly?, secure?}`; `cookies_get {url?}`; `cookies_clear {url?}`.
- `storage_get {kind: local/session, key?}`; `storage_set {kind, key, value|null}`.
- `perf_timing` -> navigation timing (ttfb, domContentLoaded, load), LCP and CLS if observed (observer injected by preload `page.ts`).

### Activity and pause

`activity.ts` exposes `wrap(name, handler)`. `registerTools` routes every `server.tool` through it. While `paused`, handlers short-circuit with `isError: "Echo is paused by the user. Ask them to resume from the toolbar."` Activity state is part of `AppState`: `{paused, count, running: string|null, recent: ActivityEntry[20]}`. Client attribution uses the client info already known to `mcp-sessions.ts` when available, else `"assistant"`.

## Renderer

Rewritten `index.html`, `styles.css`, `main.ts`, split into `main.ts` + `ui/*.ts` (palette, tabs, omnibox, settings, toasts, activity). Same element IDs for all existing controls so `connect-clients` behaviour and docs stay true.

### Visual system

- Tokens in `:root` with `[data-theme="dark"]` override and `@media (prefers-color-scheme)` for `system`. Accent indigo `#4f46e5` (light) / `#818cf8` (dark); live green `#16a34a`; danger `#dc2626`. Surfaces: `--bg`, `--surface`, `--surface-2`, `--line`, `--ink`, `--muted`.
- Font: `Inter, "Segoe UI", system-ui, sans-serif` (system fallback only; no network fonts; CSP stays `default-src 'self'`).
- 8-pt spacing, 10-14 px radii, 150 ms ease transitions, `prefers-reduced-motion` disables them.

### Shell

- Default two-row chrome 84 px; compact one-row 56 px (tabs left, omnibox center, controls right). Renderer sends `chrome:height` to main; `BrowserHub.layout()` uses the stored value instead of the `CHROME_HEIGHT` constant.
- Tabs: favicon (from `page-favicon-updated`), title, loading shimmer, close on hover, middle-click close, drag reorder (HTML5 DnD -> `tabs:reorder`), hover preview card after 500 ms (`tabs:thumbnail` returns JPEG data URL, cached 10 s). Incognito tabs get a mask icon and darker pill.
- Omnibox: security indicator, suggestions dropdown (open tabs, history top 6, "Search Google for ..."), keyboard navigation, Esc restores URL, Ctrl+L focus.
- Right controls: record button (existing), **assistant pill** (replaces LED: state dot + client name or "No assistant" + last tool + spinner + count; click -> popover with recent 20 calls and Pause/Resume button), bookmark star (Ctrl+D), menu.
- Command palette Ctrl+K / Ctrl+Shift+P: fuzzy list of actions (new tab, incognito tab, close tab, open settings sections, toggle theme, compact chrome, start/stop recording, start/end test run, copy MCP URL, copy token, pause/resume assistant, open data folder, switch to tab N).
- Toasts bottom-right for copy/connect/record/test events; existing `.note` elements stay as `aria-live` text.

### Settings

Two-pane page, full-window (as today, tab views detached). Left: search box + nav (Connections, Tools, Transfers, Activity, Recordings, Testing, Appearance, System, About, Privacy, Terms). Right: grouped cards.

- Connections/Recordings/Testing/Transfers/System/About/Privacy/Terms keep every existing ID and behaviour; Transfers gains four new group toggles and the **Allow evaluate (JavaScript)** switch with a warning.
- Tools: table of all tools, group, on/off, one-line description (generated from a static manifest shared with `register-tools`).
- Activity: recent calls table (time, client, tool, ms, result), Clear, Pause toggle.
- Appearance: theme (system/light/dark), compact chrome, home page URL.
- Settings search filters nav + card titles.

### Keyboard

Ctrl+T new tab, Ctrl+Shift+N incognito tab, Ctrl+W close, Ctrl+Tab / Ctrl+Shift+Tab cycle, Ctrl+1..9 jump, Ctrl+L omnibox, Ctrl+K palette, Ctrl+D bookmark, Ctrl+, settings, Ctrl+R reload, Alt+Left/Right back/forward, Esc stop.

## IPC additions

`settings:get/set`, `tabs:reorder`, `tabs:thumbnail`, `tabs:new-incognito`, `chrome:height`, `activity:pause`, `activity:clear`, `bookmarks:list/add/remove`, `history:search`, `tools:manifest`. Preload exposes them under the existing `window.echo` object; `AppState` gains `settings`, `activity`, `bookmarks` (count + isBookmarked for active URL), and `TabInfo.favicon/incognito`.

## Packaging

Version 1.1.0. No new runtime deps (PNG handled with `zlib`). `check-packaging.js` updated for the tool manifest and new prefs. `ECHO-SKILL-TREE.md` gains sections for the four groups and the pause state. README tool list updated.

## Testing

- `scripts/fixtures/` static pages: `forms.html`, `tables.html`, `iframes.html`, `dialogs.html`, `drag.html`, `slow.html`, `storage.html`, `perf.html`, served by `scripts/fixture-server.mjs` on 127.0.0.1:18999.
- `scripts/test-tools.mjs`: launches Echo (`ECHO_TEST=1` -> no tray popups, fixed port 18931, all groups on, evaluate on), connects with `@modelcontextprotocol/sdk` HTTP client + bearer token, runs every tool (existing 32 + new 36) against fixtures, asserts content. Exit non-zero on failure.
- Unit tests (`node --test test/unit/*.test.mjs`) for `normalizeUrl`, `visual.ts`, `history` search, `enabledToolCount`, scheduler next-run math, settings defaults/migration.
- `npm test` = unit + tools + existing `test:bridge`.

## Error handling

- Tools never throw; `err(e)` returns `isError` with a next step.
- Playwright unattached: tools that require it explain how (Echo reconnects automatically; retry once).
- Paused: explicit message (above).
- Disabled group/evaluate: message names the exact Settings switch.
- Files: all writes under `userData`, `fs` errors surfaced in tool text and toast.

## Migration

`transfer-prefs.json` missing keys get defaults (`toolsRead: true`, others `false`). `settings.json` created on first run. No changes to existing keys.
